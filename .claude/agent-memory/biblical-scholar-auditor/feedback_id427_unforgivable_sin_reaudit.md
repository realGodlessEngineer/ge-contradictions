transform-pass reroll: the discrepancy-pole named skeptic was originally Ehrman

**Why:** general lesson — a transform-pass "reroll" (re-generating a row after a
prior audit flag) must be treated as a NEW verification target, not assumed fixed
by the mere fact that a reroll happened. Always independently re-verify the named
skeptic, connective, and citations after any reroll — don't just diff against the
prior version and assume the specific flagged issue was the only thing that
changed.

**How to apply:** whenever a work file shows signs of having been regenerated
(different skeptic name, different connective wording, different pd_work) from an
earlier audit pass, re-run the full named_skeptic/connective/pd_work verification
from scratch rather than only checking whether the previously-flagged issue was
addressed — rerolls sometimes fix the flagged issue while introducing a new one.
