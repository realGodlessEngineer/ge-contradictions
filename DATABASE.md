# Database Guide — `contradictions.db`

This document describes the shared SQLite database, the SQL source files that
can recreate it, and how to read from / write to it.

The database holds skeptic-style "Bible contradiction" questions, the apologetic
answers to each, the scripture references those answers cite, and a layer of
scholarly enrichment added later by the audit pipeline. It is the single source
of truth shared (read-write by the scrapers + db_manager, read-only by the game)
across all three apps in this repo.

---

## Files

| File | What it is |
|---|---|
| `contradictions.db` | The live SQLite database (binary). Committed to the repo. |
| `db/schema.sql` | `DROP`/`CREATE` for every table and index. Recreates an empty database. |
| `db/data.sql` | One `INSERT` per row, wrapped in a transaction. Populates the schema. |
| `dumpDbToSql.js` | Regenerates `db/schema.sql` + `db/data.sql` **from** `contradictions.db`. |
| `buildDbFromSql.js` | Rebuilds `contradictions.db` **from** the two SQL files. |

`db/schema.sql` + `db/data.sql` together are a complete, text-diffable snapshot
of the database. The rebuild round-trip is **lossless** — schema, indexes, and
every row hash identically before and after.

---

## Persistence model (read this first)

The apps use **`sql.js`** (SQLite compiled to WebAssembly), *not* a native
SQLite binding. Practical consequences:

- The database is loaded entirely into memory from the file buffer. Writes
  happen in memory and **only reach disk when the app calls `db.export()` and
  writes the buffer back** (e.g. `saveDatabase()` in `db_manager/server.js`).
  A mutation that is never exported is silently lost on restart.
- **Foreign keys are not enforced by default.** The FK clauses below are
  declarative; `sql.js` does not enable `PRAGMA foreign_keys` automatically, so
  nothing stops an orphaned `answer` or `bible_reference`. The scrapers and
  `db_manager` maintain referential integrity in application code, not via the
  engine. (There is also **no `ON DELETE CASCADE`** in the live schema — deletes
  must remove children explicitly.)

## Schema

```
categories                 ──┐
contradiction_types        ──┤
scholarly_consensus_levels ──┴─< contradictions ──< answers ──< bible_references
                                       │
                                       └─< contradiction_scholarship >── scholarship_sources

rows (2026-06-12):  categories 9 · contradiction_types 10 · scholarly_consensus_levels 5 · contradictions 605 · answers 1329 · bible_references 2861 · scholarship_sources 1555 · contradiction_scholarship 3877
```

Three lookup tables (`categories`, `contradiction_types`, `scholarly_consensus_levels`)
hang off `contradictions` via FK columns; `answers` → `bible_references` is the original
parent→child chain. Two **derived** tables (`scholarship_sources` + the
`contradiction_scholarship` junction) normalize the free-text `contradictions.scholarship`
blurb into separable citations; they are regenerated by `buildScholarshipTables.js` (see
below) and are not produced by the scrapers.

### `categories`
Lookup table of the thematic category each contradiction belongs to. Referenced
by `contradictions.category_id`.

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | Stable, hand-assigned `1`–`9` (not AUTOINCREMENT). |
| `name` | TEXT NOT NULL UNIQUE | Display name, e.g. *"Jesus & the Gospels"*. |
| `description` | TEXT NOT NULL | One-line descriptor apps can surface to explain the category. |

The nine seeded categories: **Creation & Cosmology**, **God: Nature & Character**,
**Jesus & the Gospels**, **Salvation, Sin & Afterlife**, **Law, Morality & Ethics**,
**Genealogy & Identity**, **Numbers & Measurements**, **Chronology & Sequence**,
**History & Narrative Events**. Seeded (and the FK column added) by
`migrateAddCategory.js`; each contradiction is assigned exactly one via the
classification pass (`exportCategoryQuestions.js` → Sonnet scholar agent →
`applyCategoryMap.js`, or the API-keyed `classifyCategories.js`).

### `contradiction_types`
Lookup table of the *mechanism* by which a contradiction arises (orthogonal to
the thematic `categories`). Referenced by `contradictions.contradiction_type_id`.

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | Stable, hand-assigned `1`–`10` (not AUTOINCREMENT). |
| `name` | TEXT NOT NULL UNIQUE | e.g. `chronological`, `theological`, `compositional`. |
| `description` | TEXT NOT NULL | One-line descriptor apps can surface. |

The ten seeded types: **numerical**, **chronological**, **genealogical**,
**geographical**, **theological**, **ethical_legal**, **factual_historical**,
**translational**, **textual_variant**, **compositional**. Seeded (and the FK
column added) by `migrateAddContradictionType.js`; each contradiction is assigned
exactly one by the Sonnet enrichment pass (`exportEnrichmentWork.js` →
biblical-contradiction-scholar-sonnet agent → `applyEnrichmentMap.js`).

### `scholarly_consensus_levels`
Lookup table grading how mainstream critical scholarship weighs whether the
tension is a real contradiction. Referenced by `contradictions.scholarly_consensus_id`.

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK | Stable, hand-assigned `1`–`5` (not AUTOINCREMENT). |
| `name` | TEXT NOT NULL UNIQUE | `genuine_contradiction` … `apparent_only`. |
| `description` | TEXT NOT NULL | One-line descriptor apps can surface. |

The five seeded levels (strongest → weakest contradiction): **genuine_contradiction**,
**probable_contradiction**, **genuinely_disputed**, **probable_harmonization**,
**apparent_only**. Seeded (and the FK column added) by `migrateAddScholarlyConsensus.js`;
set by the Opus generator→auditor batch pipeline (`exportScholarlyBatches.js` →
`runScholarlyPipeline.js` → `mergeScholarlyToDb.js`).

### `contradictions`
The top-level question and the scholarly fields attached to it.

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK AUTOINCREMENT | |
| `question` | TEXT NOT NULL | The contradiction question, e.g. *"When was heaven created?"* |
| `question_url` | TEXT NOT NULL | Source URL on skepticsannotatedbible.com (or merged source). |
| `created_at` | DATETIME | Defaults to `CURRENT_TIMESTAMP`. |
| `summary` | TEXT | Short scholarly summary of the contradiction. Added by the enrichment pipeline. |
| `commentary` | TEXT | Longer scholarly commentary / analysis. |
| `scholarship` | TEXT | Citations and secondary-source references backing the commentary. |
| `recommend_delete` | INTEGER DEFAULT 0 | Audit cull flag (`0`/`1`): entry flagged as not a real contradiction. |
| `delete_reason` | TEXT | Free-text justification when `recommend_delete = 1`. |
| `category_id` | INTEGER | → `categories(id)`. The entry's single thematic category. Added by `migrateAddCategory.js`. |
| `testament_scope` | TEXT | `OT_internal` / `NT_internal` / `OT_vs_NT` (NULL if undetermined). Which testament(s) the tension spans. |
| `books_in_tension` | TEXT | Comma-separated canonical book names driving the scope, in canon order (e.g. `Genesis, Isaiah, John`). |
| `contradiction_type_id` | INTEGER | → `contradiction_types(id)`. The mechanism by which the contradiction arises. |
| `difficulty_level` | INTEGER | `1`–`5`: how hard the contradiction is to spot/understand (1 surface … 5 specialist). |
| `notoriety_level` | INTEGER | `1`–`5`: how widely cited/famous it is (1 obscure … 5 iconic). |
| `scholarly_consensus_id` | INTEGER | → `scholarly_consensus_levels(id)`. How critical scholarship weighs the tension. |
| `textual_variant_involved` | INTEGER | `0`/`1`: does a known manuscript/textual-critical variant materially bear on it? |
| `variant_description` | TEXT | One-sentence note on the variant (NULL when none). |
| `critical_apparatus_ref` | TEXT | Apparatus/source locating the variant, e.g. `"NA28 apparatus at John 7:53"` (NULL when none). |

> The `summary`/`commentary`/`scholarship`/`recommend_delete`/`delete_reason`
> columns were added after the original scrape by `migrateAddScholarshipFields.js`
> and `migrateAddDeleteFlag.js`, and are populated by the enrichment/audit
> pipeline (`exportBatches.js` → scholar/auditor agents → `mergeBatchesToDb.js`).
> `category_id` was added later still by `migrateAddCategory.js`. The depth fields
> are newer again: `testament_scope`/`books_in_tension` are derived *mechanically*
> from cited references by `deriveTestamentScope.js` (no LLM); `contradiction_type_id`,
> `difficulty_level`, and `notoriety_level` come from the Sonnet enrichment pass
> (`migrateAddContradictionType.js` adds the columns); and `scholarly_consensus_id`,
> `textual_variant_involved`, `variant_description`, `critical_apparatus_ref` come from
> the Opus generator→auditor batch pipeline (`migrateAddScholarlyConsensus.js` adds the
> columns). The scrapers never set any of them.

### `answers`
One or more apologetic answers per contradiction.

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK AUTOINCREMENT | |
| `contradiction_id` | INTEGER NOT NULL | → `contradictions(id)` |
| `answer` | TEXT NOT NULL | The answer/position headline. |
| `answer_explanation` | TEXT | Supporting explanation. |
| `created_at` | DATETIME | Defaults to `CURRENT_TIMESTAMP`. |

### `bible_references`
Scripture references cited by a given answer.

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK AUTOINCREMENT | |
| `answer_id` | INTEGER NOT NULL | → `answers(id)` |
| `reference` | TEXT NOT NULL | A single reference string, e.g. `"Genesis 1:1"`. |

### `scholarship_sources` (derived)
One row per distinct cited work, deduped across the corpus. Built by parsing the
prose `contradictions.scholarship` blurb into individual citations.

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK AUTOINCREMENT | |
| `author` | TEXT | Best-effort; populated for markdown-style citations, NULL for plain Chicago. |
| `title` | TEXT | Best-effort (as above). |
| `publication` | TEXT | Parenthetical publisher/series/year block when present. |
| `year` | INTEGER | Publication year (NULL for undated/ancient works). |
| `bib_core` | TEXT NOT NULL | The citation minus pages/note — the stable display identity. |
| `dedup_key` | TEXT NOT NULL UNIQUE | Order-independent token bag used to merge format variants. |
| `raw_example` | TEXT | One representative full citation string. |

> Dedup is intentionally **conservative**: it merges author-order/markdown variants
> but keeps distinct volumes apart, and may leave the same work as 2 rows when a
> publisher-city detail differs (e.g. `Zondervan` vs `Grand Rapids: Zondervan`).

### `contradiction_scholarship` (derived)
Many-to-many junction: which works each contradiction cites, with the per-use
detail. The same source is cited at different pages — and about different verses —
by different contradictions, so that detail lives here, not on the source.

| Column | Type | Notes |
|---|---|---|
| `id` | INTEGER PK AUTOINCREMENT | |
| `contradiction_id` | INTEGER NOT NULL | → `contradictions(id)` |
| `source_id` | INTEGER NOT NULL | → `scholarship_sources(id)` |
| `citation_order` | INTEGER | 1-based order the citation appeared in the original blurb. |
| `pages` | TEXT | Per-use page range, e.g. `"pp. 71-79"` (NULL when none). |
| `note` | TEXT | Per-use annotation, e.g. `"on the raqia and Priestly cosmology"`. |
| `bible_refs` | TEXT | Comma-delimited verse refs the citation points to, normalized to canonical book names, e.g. `"John 14:2"` or `"Psalms 40, Psalms 50, Psalms 51"` (NULL when none). Extracted from the annotation tail; commentary volume-title scopes are excluded. |
| `raw_citation` | TEXT NOT NULL | The full original citation chunk (authoritative; round-trips losslessly with `scholarship`). |

### Indexes
```sql
CREATE INDEX idx_answers_contradiction ON answers(contradiction_id);
CREATE INDEX idx_references_answer     ON bible_references(answer_id);
CREATE INDEX idx_contradictions_category  ON contradictions(category_id);
CREATE INDEX idx_contradictions_type      ON contradictions(contradiction_type_id);
CREATE INDEX idx_contradictions_consensus ON contradictions(scholarly_consensus_id);
CREATE INDEX idx_cs_contradiction ON contradiction_scholarship(contradiction_id);
CREATE INDEX idx_cs_source        ON contradiction_scholarship(source_id);
```

## Recreating the database

You need Node ≥ 18 and the root dependencies installed (`npm install` in the
repo root pulls in `sql.js`).

### Rebuild `contradictions.db` from SQL
```bash
node buildDbFromSql.js
```
Loads `db/schema.sql` then `db/data.sql` into a fresh in-memory database and
writes `contradictions.db`. If a `contradictions.db` already exists it is backed
up first to `contradictions.db.bak-<timestamp>`.

Options (environment variables):
```bash
OUT_PATH=./fresh.db node buildDbFromSql.js   # write somewhere else (don't touch the live DB)
SCHEMA_ONLY=1 node buildDbFromSql.js         # create an empty database (schema, no rows)
IN_DIR=./db node buildDbFromSql.js           # read SQL from a different directory
```

### Regenerate the SQL from the live database
After changing data (a new scrape, a merge, edits via db_manager), refresh the
SQL snapshot so it stays in sync:
```bash
node dumpDbToSql.js
```
Writes `db/schema.sql` and `db/data.sql` from the current `contradictions.db`.
Rows are emitted in `id` order so the output is stable and diff-friendly.

Options:
```bash
DB_PATH=./contradictions.db OUT_DIR=./db node dumpDbToSql.js
```

### Loading the SQL elsewhere (no Node)
`db/schema.sql` + `db/data.sql` are standard SQLite — load them with the
`sqlite3` CLI to get a native `.db`:
```bash
sqlite3 contradictions.db ".read db/schema.sql" ".read db/data.sql"
```

## Querying the database

### With the `sqlite3` CLI
```bash
sqlite3 contradictions.db
sqlite> .headers on
sqlite> .mode column
sqlite> SELECT id, question FROM contradictions LIMIT 5;
```

A full contradiction with its answers and references:
```sql
SELECT c.question,
       a.answer,
       a.answer_explanation,
       r.reference
FROM contradictions c
JOIN answers a            ON a.contradiction_id = c.id
LEFT JOIN bible_references r ON r.answer_id = a.id
WHERE c.id = 1;
```

Entries flagged for removal by the audit pass:
```sql
SELECT id, question, delete_reason
FROM contradictions
WHERE recommend_delete = 1;
```

Contradiction counts per category:
```sql
SELECT cat.name, COUNT(c.id) AS n
FROM categories cat
LEFT JOIN contradictions c ON c.category_id = cat.id
GROUP BY cat.id
ORDER BY n DESC;
```

Counts per mechanism type, and the most iconic / hardest entries:
```sql
SELECT t.name, COUNT(c.id) AS n
FROM contradiction_types t
LEFT JOIN contradictions c ON c.contradiction_type_id = t.id
GROUP BY t.id ORDER BY n DESC;

SELECT id, question, difficulty_level, notoriety_level, testament_scope
FROM contradictions
WHERE notoriety_level = 5 OR difficulty_level >= 4
ORDER BY notoriety_level DESC, difficulty_level DESC;
```

The "additional reading" list for one contradiction (deduped sources via the junction):
```sql
SELECT cs.citation_order, s.bib_core, cs.pages, cs.note, cs.bible_refs
FROM contradiction_scholarship cs
JOIN scholarship_sources s ON s.id = cs.source_id
WHERE cs.contradiction_id = 1
ORDER BY cs.citation_order;
```

Most-reused sources across the corpus:
```sql
SELECT s.bib_core, COUNT(DISTINCT cs.contradiction_id) AS used_by
FROM scholarship_sources s
JOIN contradiction_scholarship cs ON cs.source_id = s.id
GROUP BY s.id ORDER BY used_by DESC LIMIT 10;
```

### From Node (`sql.js`)
```js
const fs = require('fs');
const initSqlJs = require('sql.js');

(async () => {
    const SQL = await initSqlJs();
    const db = new SQL.Database(fs.readFileSync('./contradictions.db'));

    const res = db.exec('SELECT id, question FROM contradictions WHERE id = ?', [1]);
    console.log(res[0].values); // [[1, 'When was heaven created?']]

    // ---- writing ----
    db.run('UPDATE contradictions SET summary = ? WHERE id = ?', ['…', 1]);
    fs.writeFileSync('./contradictions.db', Buffer.from(db.export())); // REQUIRED to persist
    db.close();
})();
```
Remember: a write is not durable until you `db.export()` and write the buffer
back to the file. See `db_manager/server.js` (`saveDatabase()`) for the
canonical pattern, and `mergeBatchesToDb.js` for a transactional bulk update
that backs up the file first.
